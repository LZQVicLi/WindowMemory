# 窗口记忆 1.0

为这台 Apple Silicon Mac 制作的原生菜单栏工具。免费、无账户、无网络请求。已安装到 `/Applications/窗口记忆.app`。

## 日常使用

1. 第一次打开时，点“去开启权限”，在系统设置中允许“窗口记忆”控制窗口。系统版本不同，权限的中文名称可能有所变化。
2. 接上常用屏幕，打开需要的 App，把窗口摆好，点“记住当前布局”。
3. 勾选“登录时启动窗口记忆”，以后登录时自动运行。关闭主窗口后，工具继续在菜单栏工作。
4. App 启动、保存的窗口重新出现、显示器连接变化或电脑唤醒后，自动尝试恢复。也可以点“立即恢复”。
5. 改了布局后，再点一次“记住当前布局”更新。不会在你每次拖动窗口时自动覆盖保存结果。

每套屏幕组合单独保存：双屏保存一次，拔掉外接屏后也可以给单屏保存一次。遇到没有保存过的组合时，程序不会强行移动窗口。

在“已记住的窗口”列表中取消勾选，可保留记录但停止自动移动该窗口。右上角“自动归位”开关可以暂停所有自动动作；手动恢复仍可用。“…”中可以撤销上一次手动恢复、打开布局文件夹、忘记当前组合或退出。右键菜单栏图标也有快捷操作。

## 工作方式与范围

- 使用显示器 UUID 记录屏幕，保存窗口相对于可用显示区域的位置和宽高；同屏幕分辨率变化时按比例适配，并尽量把窗口限制在可见范围。
- 按 App bundle ID 识别软件；同一 App 的多个窗口优先按标题一一匹配，标题变化时再尝试部分匹配和顺序匹配。标题相同或频繁变化时，多个窗口可能互换位置。
- 新出现的窗口会按保存的槽位匹配。超出保存数量的额外窗口保持原状。
- App 启动后会在约 0.5、1.5、4 和 9 秒尝试恢复；已成功处理的窗口不会被后续启动重试反复拉回。不持续强制锁定窗口。
- 只处理普通、未最小化、非全屏窗口；不会取消最小化、退出全屏、切换虚拟桌面或启动已关闭的 App。其他 Spaces 中的窗口取决于系统是否向辅助功能 API 提供访问。
- 某些 App 有最小窗口尺寸，或拒绝调整大小。程序会显示未能完全恢复的数量，不把部分成功报告为全部成功。
- 目前构建面向 Apple Silicon，最低系统 macOS 14；在这台 macOS 27.2 上完成编译、界面检查和实际保存／恢复检查。真实插拔屏幕、睡眠唤醒和重启后的自动恢复仍需在日常使用中验证。

## 本地数据

`~/Library/Application Support/WindowMemory/layouts.json` 保存布局、App 标识和窗口标题。`layouts.previous.json` 是前一次写入前的备份。数据仅存本地，不保存屏幕内容、密码或浏览器标签页内容。源代码没有网络访问、遥测或上传逻辑。

## 源码与重新构建

- `Core.swift`：数据结构、坐标换算、多窗口匹配和 10 项自检。
- `Accessibility.swift`：macOS 辅助功能 API 读写窗口、显示器识别。
- `Controller.swift`：保存恢复、事件监听、菜单栏、登录启动。
- `main.swift`：中文控制界面和入口。
- `build.sh`：编译、打包和本地签名。

安装 Xcode 或相应命令行工具后，在本目录运行：

```sh
zsh build.sh
```

默认在源码目录的上一级生成 `窗口记忆.app`。也可把目标输出目录作为第一个参数。构建脚本会覆盖目标目录中同名的生成产物；请不要把目标目录指向尚未备份的其他版本。

仅运行自检：

```sh
"../窗口记忆.app/Contents/MacOS/WindowMemory" --self-test
```

本机运行版使用本地 ad-hoc 签名，未进行 Apple Developer ID 公证。每次重新构建后，macOS 可能要求重新允许窗口控制权限。更新前先退出运行中的版本，保留原安装路径与 bundle ID；不要同时运行两个副本。

## 卸载

先在界面关闭“登录时启动窗口记忆”，然后从“…”退出，将 `/Applications/窗口记忆.app` 移到废纸篓。若也要移除记录，再将上面的 `WindowMemory` 数据文件夹移到废纸篓。
